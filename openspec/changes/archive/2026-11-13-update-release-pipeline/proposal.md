# Change: Gate Releases on Tests and Publish Complete Artifacts

## Why
In `.github/workflows/release.yml` the PyPI `publish` job depends only on `build`: no tests and no
clean-install check run before publishing, which is how the broken 1.7.0 reached PyPI. The binary
job failed after publication, so the v1.7.0 GitHub release has zero assets while the README
promises PyInstaller binaries. The version is duplicated in `pyproject.toml` and
`undatum/__init__.py` (a local editable install reports 1.5.0 while the runtime says 1.7.0), and
the 40 KB CHANGELOG is maintained by hand although commits already follow Conventional Commits.

## What Changes
- Release order: tests → install-gate → build → binaries → manual approval → PyPI publish →
  GitHub release with all assets. Publication is the last step.
- Release candidates (`vX.Y.ZrcN` tags) publish to TestPyPI and are smoke-installed from there.
- Single source of version: `undatum.__version__` read from package metadata
  (`importlib.metadata.version`) or setuptools dynamic version.
- Changelog and version bump generated by release-please (or git-cliff) from commit history.
- Reproducibility and supply chain: `uv.lock` for CI and PyInstaller builds, `pip-audit` in CI,
  build provenance attestations for wheels, sdists and binaries.
- Run the binary build on pull requests that touch `packaging/` or `release.yml`.
- Re-issue binaries for v1.7.1.

## Impact
- Affected specs: `release-quality`, `distribution`
- Affected code: `.github/workflows/release.yml`, `.github/workflows/ci.yml`, `pyproject.toml`,
  `undatum/__init__.py`, `packaging/undatum.spec`, new `uv.lock`
