# `extensions`

Install the DuckDB extensions undatum uses, so commands work on machines without network access.
Commands never download an extension while they run: they use one only when its file is already
in the extension directory (`UNDATUM_DUCKDB_EXTENSION_DIR`, or DuckDB's default
`~/.duckdb/extensions`).

| Extension | Used for | Size (macOS / Linux, arm64) |
|---|---|---|
| `encodings` | CSV text in encodings other than UTF-8: with it, DuckDB reads Windows-1251, KOI8-R, Latin-1 and other files instead of the Python engine | 117 / 276 MB |
| `excel` | Excel workbooks | 11 / 14 MB |
| `httpfs` | HTTP(S) and S3 URLs | 19 / 25 MB |
| `spatial` | Geospatial formats and functions | 77 / 94 MB |

```bash norun
# What is installed, and where
undatum extensions list
undatum extensions list --json

# On a connected machine: download all of them, or a few, into a directory
undatum extensions install --dir /opt/duckdb-extensions
undatum extensions install encodings --dir /opt/duckdb-extensions

# On the offline machine, after copying the directory
export UNDATUM_DUCKDB_EXTENSION_DIR=/opt/duckdb-extensions
undatum extensions list
```

The extensions are built for one DuckDB version and platform (for example `v2.0.0/linux_amd64`):
install them with the same undatum and DuckDB version, on the same operating system and CPU
architecture as the offline machine. The `-full` container image includes all four (see
[Installation](/getting-started/installation)).
