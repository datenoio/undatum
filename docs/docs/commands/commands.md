# `commands`

Lists the commands, and describes them as data for scripts and agents. Everything is read from
the command tree when the command runs, so the output always matches `--help` and includes
plugin commands.

```bash
# All commands with a one-line summary
undatum commands

# The commands of a group, or the ones that mention every word of a search
undatum commands db
undatum commands --search duplicate

# The manifest: one JSON document (undatum.commands/1)
undatum commands count --json

# One agent tool definition per command
undatum commands --tools
```

## Manifest

`--json` prints a `undatum.commands/1` document
([JSON Schema](https://datenoio.github.io/undatum/schemas/undatum.commands.v1.json)):

| Key | Content |
|---|---|
| `undatum_version` | The undatum version that printed it |
| `exit_codes` | Exit code → meaning (the same for every command) |
| `global_options` | Options of `undatum` itself (`--verbose`, `--quiet`, ...) |
| `groups` | Command groups (`db`, `formats`, ...) with their summaries |
| `commands` | One entry per command (below) |

Each command entry has:
- `name`, `summary`, `help` and `examples` (from the `Examples:` section of its help);
- `usage` and `arguments`;
- `options`. For each option:
  - `name` (the canonical long flag in snake case, `format_in`), `flags` (`--format-in`, `-F`)
    and `negation` (`--no-...`);
  - `type` (`string`, `integer`, `number` or `boolean`), `choices`, `default` and `required`;
  - `multiple` (the option can repeat), `flag` (it takes no value) and `count` (it counts, as
    `-vv` does);
  - `deprecated_flags`: old spellings that still work until 2.0;
- `engines`: `auto`, `duckdb`, `python` for commands with `--engine`; `python` for other data
  commands; `null` for the rest;
- `capabilities`: what the command reads and writes and how much memory it needs, as on the
  command pages;
- `results`: the layouts of its JSON output (`undatum.count/1`), each with the options that
  select it (`when`: `--rules` for `validate`), or an empty list;
- `deprecated`.

## Tool definitions

`--tools` prints a JSON array with one tool per command, in the shape of
[`undatum mcp tools --json`](/commands/mcp): `name` (`undatum_count`, `undatum_db_query`),
`description` and `parameters` (JSON Schema). Parameters are named after the arguments and the
long options (`--format-in` is `format_in`); repeatable options and arguments are arrays.

An agent framework runs a tool call with `tool_argv()`, which turns it back into the command line:

```python
import subprocess

from undatum.cli.manifest import tool_argv

argv = tool_argv("undatum_count", {"input_file": "data.csv", "format_in": "csv", "json": True})
# ['count', '--format-in', 'csv', '--json', 'data.csv']
subprocess.run(["undatum", *argv], check=True)
```

Unknown tools and parameters raise `UndatumError`. The MCP server (`undatum mcp serve`) exposes a
smaller set of read-only tools with a sandbox; `--tools` describes the whole CLI, for agents that
run shell commands themselves.
